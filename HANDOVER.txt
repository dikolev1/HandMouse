3. GOLDEN RULE: THE APP RESTARTS ITSELF WHEN hand_mouse.py IS SAVED
======================================================================
AUTO_RESTART_ON_EDIT = True: about 1 s after hand_mouse.py changes, the running app restarts itself. A syntax error
or a crash at import kills it and the user loses their mouse. So NEVER edit hand_mouse.py in place. Workflow used
for every change so far:
  1. Copy hand_mouse.py, tests\, README.md, CLAUDE.md to a scratch folder. Check first that the scratch copy equals
     the live files (diff -q), the user sometimes changes things.
  2. Edit there. Lint:  <python> -m pyflakes hand_mouse.py   (pyflakes is installed)
  3. Reproduce the problem in a test (see section 5), fix, run the whole suite:  <python> tests\run_tests.py
     (23 test files, a few minutes; all must pass). Also run the new checks against the CURRENT live version to
     show "before: fails, after: passes".
  4. cp hand_mouse.py hand_mouse_previous.py   (backup of the version before the change, by convention)
     Copy docs/tests in, then copy hand_mouse.py in LAST.
  5. Watch hand_mouse.log for: "hand_mouse.py changed, restarting" -> "started (...)" -> "camera ready in N s",
     and no ERROR / fatal. (Traceback lines have no timestamp; don't mistake old ones for new.)
  6. git add -A; commit (message: what was wrong, from which evidence, what changed, tests); git push origin develop.

5. HOW TO DIAGNOSE (the method that worked: measure, then change)
======================================================================
- hand_mouse.log (rotates at 2 MB, plus .1/.2):
    * a "diag" line every second with fps, ms/frame and each hand's numbers: fingers (extension of index..pinky,
      ~1.0 folded, ~1.8 straight), t-mid / t-ring / t-idx = thumb-to-fingertip distance in 3D with "(2d ...)" =
      the same in the picture, t-ring-base = button-5 area distance, size = hand size vs normal.
    * every gesture event; every left-hand touch: "second hand touch 0.19 s, 7 frames: thumb to index A middle B
      ring C (median, picture a b c) ... -> decision (too short / cancelled: ...)".
    * every play/pause: "second hand thumbs-up X s, thumb out up to Y, hand size Z".
- debug\ folder (when debug mode is on): one JPEG per recognised gesture = 8 camera frames from the last 1.2 s
  with the hands drawn and per-frame numbers under each frame ("idx 3D/2D mid 3D/2D ring 3D/2D thumb <thumb_out>").
  File names start with date_time, matching the log. Newest 500 kept. You can open them with the Read tool.
  Re-running MediaPipe on these frames does NOT work (drawn skeleton, small size) - read the printed numbers.
- When the user says "X doesn't work" or "X fires by itself": find the log lines / debug pictures at that time,
  read the numbers, then reproduce with synthetic hands in a test.
- Tests use synthetic hands (tests\test_core.py: make(px, py, pinch, fist, fold, label, jitter)), FakeMouse records
  events (buttons, wheel, hwheel, keys, osk). To replay real readings, override the cached properties, e.g.
  h.__dict__["pinch"] = (0.40, 0.58); h.__dict__["side"] = {"x1": 0.35, "x2": math.inf}; h.__dict__["ext"] = [...]
  Other helpers: tests\test_second_keys.py (left(), both(), thumbs(), run_w(), run_small()),
  tests\test_buttons_4_5.py (with_thumb()).
- Watch out when writing tests: a fake hand that jumps more than MATCH_DISTANCE (0.25) in one frame becomes a NEW
  hand (new track) - move hands gradually. Fake-hand distances are not real-hand distances (e.g. the fake middle
  pinch reads index 0.23 / middle 0.16).

======================================================================
6. THINGS LEARNED IN THE LAST SESSIONS (more in CLAUDE.md "Lessons learned")
======================================================================
- MediaPipe's 3D depth guess is often far off for thumb-to-fingertip distances (left "OK" sign read 0.5-0.65
  while held; right thumb on middle tip read 0.6-1.09). The picture (2D) distance was right every time. Several
  rules now use 2D as a helper: INDEX_HOLD_2D / INDEX_START_2D (left Alt+Tab pinch), CLICK_2D and CLICK_2D_FAR
  (right clicks; the far one only with the palm facing the camera, facing >= SIDE_FACING), and the left-hand
  finger choice uses per-frame min(3D, 2D).
- The frame rate went from ~14 to ~27 fps (camera window closed; 9-10 fps with it open). Rules counted in frames
  changed meaning: clicks now need 2 frames AND CLICK_DELAY (0.08 s).
- Relaxed / resting hands produce gestures by themselves (fingers read ~1.3, thumb wobbles). Guards added: fully
  in view, real thumbs-up (thumb_out >= 0.5, held 0.3 s), repeat limits, one direction per thumbs-up.
- A hand coming into view from the picture edge is misread: left-hand touches can't start then (fully_in_view).

2026-11-06 main-hand switching: either hand can toggle sides with two quick fist-open cycles,
with one or both visible. Per-track detection and a 0.6 s cooldown prevent duplicate swaps.
Thumb-out music poses do not count. Esc now waits 0.5 s to avoid firing during quick fists.

Camera-edge safety border: the whole moving cursor box stays inside a visible blue inset,
roughly one hand-width from the image edges (14% horizontally, 18% vertically).
Following, resizing, distance scaling and saved positions all respect this boundary.
The screen edges remain reachable at the cursor-box edges. This reserves space for gestures;
it does not prevent the user from physically moving their hand outside the camera image.

L-pose recognition uses thumb spread relative to the index axis, normalized by palm size,
instead of the rotating finger bounding box. A narrower projected thumb/index angle is accepted
with release hysteresis; folded-finger, fingertip-separation and full-visibility checks remain.
Photo-derived landmark tests cover sizes, rotations, both sides and tucked/parallel-thumb rejection.

negative monitor origins. Rejected delivery is logged at most once per five seconds;

uses a consistent input stream for overlays; it does not bypass UIPI, UIAccess or secure
desktop restrictions. Real OSK/Snipping Tool verification is still required. Recent logs

Wake feedback (1.0.7): a short high beep at 1.5 seconds means the fist hold is sufficient:
